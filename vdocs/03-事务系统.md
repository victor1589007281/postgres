## 1. 事务概述

PostgreSQL完整支持ACID特性（原子性、一致性、隔离性、持久性），是企业级数据库的核心能力。

### 1.1 ACID实现机制

```mermaid

    subgraph "**ACID特性实现**"

        style I fill:#ffccbc,stroke:#bf360c,stroke-width:3px

        A[**原子性 Atomicity**<br/>━━━━━━━━━━━━━━━━<br/>实现机制:<br/>• WAL预写日志<br/>• 事务提交/回滚日志<br/>• CLOG记录事务状态<br/>━━━━━━━━━━━━━━━━<br/>保证: 要么全部执行成功<br/>要么全部回滚]
        
        C[**一致性 Consistency**<br/>━━━━━━━━━━━━━━━━<br/>实现机制:<br/>• 约束检查外键、唯一<br/>• 触发器<br/>• 规则系统<br/>━━━━━━━━━━━━━━━━<br/>保证: 数据库从一个<br/>一致状态转换到另一个<br/>一致状态]
        
        I[**隔离性 Isolation**<br/>━━━━━━━━━━━━━━━━<br/>实现机制:<br/>• MVCC多版本并发控制<br/>• 事务快照Snapshot<br/>• 锁机制Lock Manager<br/>━━━━━━━━━━━━━━━━<br/>保证: 并发事务互不干扰<br/>支持4种隔离级别]
        
        D[**持久性 Durability**<br/>━━━━━━━━━━━━━━━━<br/>实现机制:<br/>• WAL预写日志<br/>• fsync强制刷盘<br/>• 检查点Checkpoint<br/>━━━━━━━━━━━━━━━━<br/>保证: 提交的事务<br/>永久保存不丢失]
    end
    
    A --> C
    C --> I
    I --> D
```

### 1.2 事务处理流程

```mermaid
sequenceDiagram
    participant Client as **客户端**
    participant Backend as **Backend进程**
    participant XactMgr as **事务管理器**
    participant CLOG as **CLOG**
    participant WAL as **WAL日志**
    participant Buffer as **缓冲区**
    
    Client->>Backend: **BEGIN**
    Backend->>XactMgr: **StartTransaction**
    XactMgr->>XactMgr: **分配事务ID XID**
    XactMgr->>XactMgr: **获取快照Snapshot**
    XactMgr-->>Backend: **事务状态: IN_PROGRESS**
    
    Client->>Backend: **INSERT/UPDATE/DELETE**
    Backend->>Buffer: **修改数据页**
    Backend->>WAL: **写WAL日志**<br/>XLOG_HEAP_INSERT等
    Backend->>Buffer: **标记页面为脏**
    
    Client->>Backend: **COMMIT**
    Backend->>XactMgr: **CommitTransaction**
    XactMgr->>WAL: **写COMMIT日志**<br/>XLOG_XACT_COMMIT
    WAL->>WAL: **fsync刷盘**
    XactMgr->>CLOG: **标记XID为COMMITTED**
    XactMgr->>Backend: **释放锁**
    XactMgr->>XactMgr: **清理事务状态**
    Backend-->>Client: **COMMIT成功**
    
    Note over Client,Buffer: **如果ROLLBACK**
    Client->>Backend: **ROLLBACK**
    Backend->>XactMgr: **AbortTransaction**
    XactMgr->>WAL: **写ABORT日志**<br/>XLOG_XACT_ABORT
    XactMgr->>CLOG: **标记XID为ABORTED**
    XactMgr->>Backend: **释放锁**
    Backend-->>Client: **ROLLBACK成功**
```

## 2. 事务ID管理

### 2.1 事务ID（XID）分配

PostgreSQL使用32位无符号整数作为事务ID，范围是0到2^32-1（约42亿）。

```mermaid
graph LR
    subgraph "**事务ID空间**"
        style Special fill:#ffccbc,stroke:#bf360c,stroke-width:3px
        style Normal fill:#c8e6c9,stroke:#2e7d32,stroke-width:3px
        style Wraparound fill:#fff9c4,stroke:#f57f17,stroke-width:3px
        
        Special[**特殊XID**<br/>━━━━━━━━━━━━━━━━<br/>0: InvalidXID<br/>1: BootstrapXID<br/>2: FrozenXID<br/>3: FirstNormalXID]
        
        Normal[**正常XID范围**<br/>━━━━━━━━━━━━━━━━<br/>3 到 2^32-1<br/>━━━━━━━━━━━━━━━━<br/>约42亿个事务<br/>循环使用]
        
        Wraparound[**XID回卷问题**<br/>━━━━━━━━━━━━━━━━<br/>达到20亿后必须VACUUM<br/>否则会发生回卷<br/>━━━━━━━━━━━━━━━━<br/>FrozenXID标记老旧元组<br/>避免回卷导致数据丢失]
    end
    
    Special --> Normal
    Normal --> Wraparound
```

### 2.2 XID比较规则

由于XID是循环使用的，不能简单用数值大小比较，而是使用模运算。

```mermaid
        Future[**未来事务**<br/>━━━━━━━━━━━━━━━━<br/>XID在 1001到2^32-1<br/>━━━━━━━━━━━━━━━━<br/>距离>21亿<br/>认为是未来的事务]
    end
    
    Past -.->|**已提交**| Current
    Current -.->|**未分配**| Future
```

**关键函数**: `TransactionIdPrecedes()` 在 `src/include/access/transam.h`

```c
// 判断xid1是否在xid2之前
bool TransactionIdPrecedes(TransactionId xid1, TransactionId xid2)
{
    int32 diff = (int32)(xid1 - xid2);
    return (diff < 0);
}
```


- `vacuum_freeze_table_age`: 默认150,000,000（1.5亿）
- `autovacuum_freeze_max_age`: 默认200,000,000（2亿，强制VACUUM）

## 3. 事务隔离级别

PostgreSQL支持SQL标准定义的4种隔离级别，但实际实现只有3种（READ UNCOMMITTED等同于READ COMMITTED）。

### 3.1 隔离级别对比

```mermaid
graph TB
    subgraph "**隔离级别金字塔**"
        style RU fill:#ffccbc,stroke:#bf360c,stroke-width:3px
        style RC fill:#fff9c4,stroke:#f57f17,stroke-width:3px
        style RR fill:#c8e6c9,stroke:#2e7d32,stroke-width:3px
        style S fill:#bbdefb,stroke:#1565c0,stroke-width:3px
        
        RU[**READ UNCOMMITTED**<br/>读未提交<br/>━━━━━━━━━━━━━━━━<br/>PG中等同于READ COMMITTED<br/>不支持脏读]
        
        RC[**READ COMMITTED 默认**<br/>读已提交<br/>━━━━━━━━━━━━━━━━<br/>• 每条语句获取新快照<br/>• 只能看到已提交数据<br/>• 可能出现不可重复读<br/>• 可能出现幻读<br/>━━━━━━━━━━━━━━━━<br/>性能最好，并发度最高]
        
        RR[**REPEATABLE READ**<br/>可重复读<br/>━━━━━━━━━━━━━━━━<br/>• 事务开始时获取快照<br/>• 整个事务看到一致数据<br/>• 避免不可重复读<br/>• 避免幻读通过快照<br/>• 更新冲突时报错<br/>━━━━━━━━━━━━━━━━<br/>适合报表、一致性读]
        
        S[**SERIALIZABLE**<br/>可串行化<br/>━━━━━━━━━━━━━━━━<br/>• 基于REPEATABLE READ<br/>• 增加SSI检测<br/>• 检测读写依赖<br/>• 可能序列化失败<br/>━━━━━━━━━━━━━━━━<br/>最严格，性能最低]
    end
    
    RU --> RC
    RC --> RR
    RR --> S
```

### 3.2 隔离级别现象对比表

| **隔离级别** | **脏读** | **不可重复读** | **幻读** | **序列化异常** |
|-------------|---------|---------------|---------|---------------|
| **READ UNCOMMITTED** | ❌ 不会 | ✅ 可能 | ✅ 可能 | ✅ 可能 |
| **READ COMMITTED** | ❌ 不会 | ✅ 可能 | ✅ 可能 | ✅ 可能 |
| **REPEATABLE READ** | ❌ 不会 | ❌ 不会 | ❌ 不会 | ✅ 可能 |
| **SERIALIZABLE** | ❌ 不会 | ❌ 不会 | ❌ 不会 | ❌ 不会 |

## 4. 锁机制

### 4.4 行锁模式

| **锁模式** | **SQL命令** | **冲突锁** | **用途** |
|-----------|-----------|-----------|---------|
| **FOR KEY SHARE** | `SELECT ... FOR KEY SHARE` | FOR UPDATE | 防止删除和主键修改 |
| **FOR SHARE** | `SELECT ... FOR SHARE` | FOR UPDATE<br/>FOR NO KEY UPDATE | 防止修改和删除 |
| **FOR NO KEY UPDATE** | `SELECT ... FOR NO KEY UPDATE` | FOR SHARE<br/>FOR NO KEY UPDATE<br/>FOR UPDATE | 防止修改和删除，允许键共享 |
| **FOR UPDATE** | `SELECT ... FOR UPDATE`<br/>UPDATE/DELETE | 所有其他锁 | 独占锁，防止任何修改 |

## 5. 死锁检测

PostgreSQL使用**等待图（Wait-For Graph）**算法检测死锁。

### 5.1 死锁检测机制

```mermaid
sequenceDiagram
    participant T1 as **事务T1**
    participant T2 as **事务T2**
    participant LM as **锁管理器**
    participant DD as **死锁检测器**
    
    T1->>LM: **锁定行A**
    LM-->>T1: **成功**
    
    T2->>LM: **锁定行B**
    LM-->>T2: **成功**
    
    T1->>LM: **请求锁定行B**
    LM->>LM: **等待T2释放**
    
    T2->>LM: **请求锁定行A**
    LM->>LM: **等待T1释放**
    
    Note over LM,DD: **形成循环等待**
    
    LM->>DD: **启动死锁检测**<br/>deadlock_timeout后
    DD->>DD: **构建等待图**<br/>T1→T2→T1
    DD->>DD: **检测到环**
    
    DD->>T2: **选择牺牲者**<br/>回滚代价小的事务
    T2-->>Client: **ERROR: deadlock detected**
    
    T1->>LM: **获得行B的锁**
    T1->>T1: **继续执行**
```

### 5.3 避免死锁的最佳实践

1. **按相同顺序访问对象**: 所有事务按ID排序访问行
2. **缩短事务时间**: 减少锁持有时间
3. **使用较低隔离级别**: READ COMMITTED而非SERIALIZABLE
4. **使用SELECT FOR UPDATE NOWAIT**: 立即失败而非等待
5. **合理设置超时**: `deadlock_timeout`（默认1秒）

## 6. 两阶段提交

两阶段提交（2PC）用于分布式事务，确保跨多个数据库的事务原子性。

### 6.1 2PC流程

```mermaid
sequenceDiagram
    participant Coordinator as **协调者**
    participant PG1 as **PostgreSQL节点1**
    participant PG2 as **PostgreSQL节点2**
    
    Note over Coordinator,PG2: **阶段1: PREPARE准备阶段**
    
    Coordinator->>PG1: **BEGIN**
    Coordinator->>PG1: **执行SQL操作**
    Coordinator->>PG1: **PREPARE TRANSACTION 'txn_001'**
    PG1->>PG1: **写WAL日志**<br/>持久化事务状态
    PG1-->>Coordinator: **PREPARE成功**
    
    Coordinator->>PG2: **BEGIN**
    Coordinator->>PG2: **执行SQL操作**
    Coordinator->>PG2: **PREPARE TRANSACTION 'txn_001'**
    PG2->>PG2: **写WAL日志**<br/>持久化事务状态
    PG2-->>Coordinator: **PREPARE成功**
    
    Note over Coordinator,PG2: **阶段2: COMMIT提交阶段**
    
    Coordinator->>PG1: **COMMIT PREPARED 'txn_001'**
    PG1->>PG1: **最终提交**
    PG1-->>Coordinator: **COMMIT成功**
    
    Coordinator->>PG2: **COMMIT PREPARED 'txn_001'**
    PG2->>PG2: **最终提交**
    PG2-->>Coordinator: **COMMIT成功**
    
    Note over Coordinator,PG2: **如果任一节点失败**
    Coordinator->>PG1: **ROLLBACK PREPARED 'txn_001'**
    Coordinator->>PG2: **ROLLBACK PREPARED 'txn_001'**
```

### 6.2 2PC状态管理

```mermaid
graph TB
    Start[**事务开始**] --> Execute[**执行SQL**]
    Execute --> Prepare{**PREPARE**}
    
    Prepare -->|**失败**| Abort1[**直接回滚**]
    Prepare -->|**成功**| Prepared[**PREPARED状态**<br/>持久化到pg_twophase/]
    
    Prepared --> Decide{**协调者决策**}
    
    Decide -->|**COMMIT PREPARED**| Commit[**提交成功**<br/>清理状态文件]
```

## 总结

PostgreSQL的事务系统是其ACID保证的核心：

1. **完整的ACID支持**: 通过WAL、MVCC、锁机制和CLOG实现
2. **灵活的隔离级别**: 支持4种隔离级别，默认READ COMMITTED
3. **高效的锁机制**: 多层次锁（表锁、页锁、行锁）平衡并发性
4. **智能死锁检测**: 自动检测和解决死锁问题
5. **分布式事务支持**: 通过2PC实现跨库事务

**关键特性**:
- **事务ID循环使用**: 需要VACUUM FREEZE防止回卷
- **MVCC实现隔离**: 读不阻塞写，写不阻塞读
- **行级锁存储在元组头**: 避免额外的锁表查找
- **SSI实现可串行化**: 检测读写依赖，避免异常

**配置建议**:
- `default_transaction_isolation`: 默认READ COMMITTED
- `deadlock_timeout`: 死锁检测延迟，默认1秒
- `max_prepared_transactions`: 2PC最大数量，默认0（禁用）
